    Agents Meet APIs: Gemini Enterprise Agent Platform × Apigee — Architecture

    Apigee X
    STEP 1

    Agent identity

    Each agent on Agent Runtime has its own Agent Identity (the RM Agent and the Insights Agent are different principals); all egress is bound to Agent Gateway.

    STEP 2

    Agent Gateway

    Registry + IAM access policies decide where the agent may go; a content check calls Model Armor on what goes out and comes back.

    STEP 3

    Apigee X

    MCP tools, the paid credit bureau and the LLM gateway: API products, on-behalf-of user tokens (sub = user, act = agent), user limits, paid-API quotas, model routing.

    PARTNER

    Second front door

    FinPal (outside GCP) reaches the same MCP tools through Apigee only, with its own product and quota.

    IAM

    Agent → Google data

    The RM Agent reads BigQuery as itself. IAM grants its identity one table; everything else is refused. Every run's deciding layer lands in the Audit Log.
